# Deploy — Correções + RLS por role (2026-05-30)

Pacote pronto para aplicar em produção. Como as migrations anteriores foram
aplicadas pelo **SQL Editor**, este runbook segue o mesmo caminho (sem CLI).

---

## ⚠️ Antes de tudo: BACKUP
Dashboard → **Database → Backups** (ou rode e salve o resultado de
`select * from public.colaboradores;`). A migration 2 é **destrutiva** (dropa colunas
de `colaboradores` após copiá-las para `colaboradores_remuneracao`).

## Ordem de aplicação (importa!)

1. Conteúdo de **`supabase/migrations/20260530_correcoes-rapidas.sql`**
   (cria `meu_role()`, corrige `profiles_update`, trigger de numeração de orçamento,

2. Conteúdo de **`supabase/migrations/20260530_rls-por-role.sql`**

Faça o deploy **junto** com o SQL. Se as policies entrarem antes do front, um
gerente pode ver toasts de "Sem permissão" até o front novo subir (comportamento
esperado, não quebra dados).

```js
// deve retornar [] (RLS filtra), NÃO o ledger:
(await db.from('lancamentos').select('*')).data

```

## Rollback (se algo der errado)
- As policies podem ser revertidas recriando a policy `*_all` antiga
  (`for all using (workspace_id = public.meu_workspace_id())`) em cada tabela.
- O split de colaboradores **não** é trivialmente reversível (colunas dropadas) —
  por isso o **backup** é obrigatório. Para reverter: recriar as colunas e
  `update colaboradores c set salario = r.salario ... from colaboradores_remuneracao r
   where r.colaborador_id = c.id`.
