Pacote do PR #19. Como as migrations anteriores foram aplicadas pelo
**SQL Editor**, este runbook segue o mesmo caminho (sem CLI).

Resumo da entrega:
- Kanban em raias horizontais (cards em linha por etapa), cards uniformes.
- Novas etapas: **Preparação, Pintura, Polimento**; renomeações (Aguardando

## Validação pós-deploy

### A) No SQL Editor
```sql
-- a constraint deve listar as 9 etapas
select pg_get_constraintdef(con.oid)
  from pg_constraint con
  join pg_class rel on rel.oid = con.conrelid
 where rel.relname = 'veiculos' and con.conname = 'veiculos_status_check';
-- esperado: status = ANY ... 'preparacao','pintura','polimento' ... presentes
```

### B) No app
- Kanban abre em raias horizontais; etapas Preparação/Pintura/Polimento existem.
- Arrastar (ou "→ Mover") um card para **Preparação**, **Pintura** e
  **Polimento** funciona, **sem** o toast de erro de constraint.
- Faixa **Entregue** mostra só entregas do mês atual.

## Rollback
Reverter a constraint para a lista antiga (só faça se precisar voltar o front
também — senão cards já movidos p/ etapas novas violariam a constraint):
```sql
alter table public.veiculos drop constraint if exists veiculos_status_check;
alter table public.veiculos
  add constraint veiculos_status_check
  check (status in ('aguardando','em-andamento','aguardando-pecas',
                    'pronto','entregue','cancelado'));
```
